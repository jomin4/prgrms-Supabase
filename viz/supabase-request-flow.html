Supabase에 접근하는 세 가지 방식을 보여주는 인터랙티브 다이어그램. 앱(supabase-js)은 Kong 게이트웨이와 API 서비스를 거쳐 PostgreSQL에 닿으며 RLS가 적용된다. SQL Editor와 DB 툴은 API를 거치지 않고 PostgreSQL에 직접 접근하며 RLS를 우회한다. 방식을 고르고 요청 보내기를 누르면 패킷이 경로를 따라 흐른다.

Supabase 접근 방식 & 아키텍처

같은 PostgreSQL에 닿는 세 가지 경로. API 경로만 RLS로 보호되고, 직접 경로는 RLS를 우회합니다.

초록 경로 = RLS 보호 (anon 키로 안전) 주황 경로 = RLS 우회 (DB 자격증명 · 서버/관리자 전용)

    💡 셋 다 결국 같은 PostgreSQL에 닿지만, API 경로만 RLS 검사를 거칩니다. 그래서 브라우저엔 anon 키만 두고(그래도 안전), service_role 키·DB 비밀번호는 서버에서만 씁니다.
